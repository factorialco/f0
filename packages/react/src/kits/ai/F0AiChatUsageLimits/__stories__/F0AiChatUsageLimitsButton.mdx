# AI chat usage limits

Shows how much of their One allowance the viewer has used, as a percentage, from
a compact ring that opens a popover. One settings managers can also see the
company allowance and jump to the company usage view. The component never
mentions credits: One is sold as capacity to get work done, so usage reads as
"30% used", "Unlimited", or an exhausted red state.

### Content best practices

- Section labels come from the host and must already be localized. Reuse the
  words of the usage page: "Company allowance", "Personal allowance".
- Keep labels to two or three words so the row fits beside "100% used".

### Behavior

- WHEN <code>usage</code> is <code>null</code> → THEN the ring is empty and the popover shows a skeleton.
- WHEN <code>error</code> is true → THEN the popover shows only the error line.
- WHEN <code>usedPercentage</code> is 100 or more → THEN the ring and the bar turn red.
- WHEN <code>unlimited</code> is true → THEN the ring and the bar are neutral and the value reads "Unlimited".
- WHEN <code>onSeeCompany</code> or <code>sections</code> are provided → THEN a bottom section appears below a divider.
- WHEN the popover opens or closes → THEN <code>onOpenChange</code> fires with the new state.

## Accessibility

The ring is decorative. The trigger button carries a visually hidden name that
includes the value, for example "Personal allowance: 30% used", and exposes{" "}

<code>aria-expanded</code> and <code>aria-haspopup="dialog"</code>. Each bar is
a <code>progressbar</code> named after its row with the ARIA value attributes
set.

### Screen reader behavior

- The trigger announces the row title and the current value; the ring SVG is hidden.
- Bars announce their row label and percentage through the <code>progressbar</code> role; an unlimited bar is an image named "Unlimited".
- The skeleton is <code>aria-busy</code> with a polite live region.
