# AI insight card

Presents a single AI-surfaced insight as a fixed-size card (217×200). The card
can act as one button and reveals an optional Ask One action on hover or focus.

## Anatomy

Every card has a heading, an optional description on top, and a content area
picked by the `content` prop: plain text, a person, a group of people, a team,
a company, an alert tag, a balance amount, or a sparkline chart.

### Content best practices

- Write headings as findings ("3 employees with expiring contracts"), not
  labels ("Contracts").
- Use the description for the scope or source of the insight, in a couple of
  words.
- For sparkline content the `label` is the visible delta pill; keep it short
  ("+992", "-15%").

### Behavior

- WHEN <code>onClick</code> is provided → THEN the whole card becomes a
  <code>role="button"</code> target, activatable with <kbd>Enter</kbd> and
  <kbd>Space</kbd>.
- WHEN <code>onAskOne</code> is provided → THEN the Ask One action appears on
  hover or focus, rendered outside the card's button subtree.
- WHEN both are provided → THEN the two actions stay independent: activating
  Ask One never triggers the card's <code>onClick</code>.
- WHEN <code>selected</code> is true → THEN the animated gradient border is
  drawn around the card.

## Accessibility

- The card root is a <code>role="button"</code> only when <code>onClick</code>
  is passed; its accessible name comes from the visible description, heading
  and label text.
- The Ask One button is a real <code>&lt;button&gt;</code> rendered as a
  sibling of the card surface, never nested inside the card's button role, so
  both actions are exposed to assistive technology independently.
- The sparkline is exposed as <code>role="img"</code> with an aria-label
  derived from the data trend (positive, negative or neutral), honoring
  <code>invertStatus</code>.
- The skeleton announces itself with <code>aria-busy</code> and
  <code>aria-live="polite"</code>.
- Reveal and fade animations respect the user's reduced-motion preference.
