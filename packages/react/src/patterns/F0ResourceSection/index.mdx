# Resource section

One section of the overview on a `Resource page`. The overview is built by stacking sections, each holding one kind of content under an optional heading with its own action:

- **`details`** holds label and value pairs, the resource's own attributes: an employee's work information, a workplace's address, a legal entity's tax details.
- **`cards`** holds a grid of things the reader can open, like the teams a person belongs to. Each card is an `F0Card`, the same card the data collection's card view renders, so a team looks the same here as it does anywhere else.

More variants will follow, so a page composed of sections today keeps working when they arrive.

For editing many fields at once use `F0Form`; for a single dense list of rows with borders use `DetailsItemsList` with `tableView`.

The header is a `SectionHeader`, so it takes a title, an optional description and an optional action on the right. Below it the fields arrange into two columns, dropping to one at the same breakpoint where the resource header stops being a row and stacks its actions: one column and a stacked header are the same narrow layout. Each field shows its label in secondary text above its value.

### Content best practices

- **Labels name the field, not the action.** "Personal email", not "Enter personal email".
- **Keep labels short enough to sit on one line** in a narrow column.
- **Leave values alone when they are empty.** The placeholder handles it; do not write "None" or "N/A" into the value.

### Behavior

- **Items are children**, so a field that only sometimes applies is a plain conditional. There is no list to build up beforehand.
- **Sections divide themselves.** Every section but the first in a stack puts 64px of space above itself, and the headings are rule enough: no line is drawn. The space is half margin, half padding, so a jump from the page's rail, which aligns to the section's edge, still leaves 32px of air above the heading. **Stack sections with no gap of your own**: a container gap adds to this and pulls each heading away from its own fields.
- **The header action is ghost**, so an Edit that belongs to one section does not read as loudly as the page's own actions. Pass `variant` on the action to override it.
- **An empty value shows a placeholder**, `--` by default, and the item stays on the page. Pass `placeholder` to change the text.
- **Two columns by default**, dropping to one at the breakpoint where the resource header stacks its actions. Pass `columns={1}` for narrow places like a side rail.
- **The cards variant lays out its own grid**, three across on a wide page, two at medium and one when narrow. `columns` does not apply to it.
- **A header with no description stays tight** to the items: the description renders nothing when omitted.
- **Values can do more than sit there.** Anything `DetailsItem` supports works, including values that copy to the clipboard or link somewhere.

## Accessibility

- **The heading is a real `h2`**, from `SectionHeader`, so the section appears in the page's heading outline and screen reader users can jump to it.
- **Labels are read before their values**, because each item puts the label first in the reading order.
- **Empty fields are announced**, since the placeholder is real text rather than a blank space. A reader hears the field exists and has no value.
- **The header action is a button** with its label as its accessible name, and it is reachable from the keyboard in the same order it appears.
