# Data Collection/Visualizations

## Introduction

Visualizations are the way to display the data in the collection.

Data collection abstracts the data (including, filtering, sorting, grouping,
etc.) and the visualization, of the data at item level (visualization) and
[cell level](?path=/docs/data-collection-cell-types--docs).

## Switching between visualizations

When you pass more than one visualization, Data Collection renders a view
switcher (a segmented control) in the header. Each chip shows the
visualization's icon and label.

## Customizing the switcher chips

By default each built-in visualization uses its localized name — "Table",
"Graph", "List", etc. — and the icon registered for its type. To tailor a chip
for a specific collection, pass an optional `label`, `icon`, or both on the
visualization. Different collections can present the same type differently —
e.g. the `graph` view as "Org chart" for employees, or the `table` view as
"Teams" for teams.

```tsx
<OneDataCollection
  source={dataSource}
  visualizations={[
    // Renames the chip to "Org chart"; the built-in graph icon is kept.
    { type: "graph", label: "Org chart", options: {} },
    // Presents the editable table as a plain table, icon included.
    { type: "editableTable", label: "Table", icon: Table, options: {} },
    // Omit both to keep the defaults ("Table" with the table icon).
    { type: "table", options: {} },
  ]}
/>
```

- Both are optional and independent; when omitted the localized built-in label
  and the built-in icon are used, so existing collections keep showing "Table"
  and "Graph" unchanged.
- Overriding these only changes how the chip presents the view — the
  visualization still behaves as its `type`. To add a view F0 doesn't provide,
  use a `type: "custom"` visualization instead.
