# F0GraphNode

F0GraphNode renders an interactive item inside an `F0Graph` hierarchy. It adapts its content and silhouette to the graph zoom level while preserving tree semantics, selection state, and keyboard navigation.

## Anatomy

<Canvas of={Stories.Default} />

<Controls of={Stories.Default} />

The node has four visual regions:

1. **Avatar**: a fixed 40 × 40 identity marker rendered at `size="lg"`
2. **Text column**: the primary title and, in the detail variant, an optional subtitle
3. **Metadata row**: optional tags rendered below detail nodes
4. **Action slot**: a floating `NodeToolbar` shown above selected detail nodes

### Content best practices

Use a short, identifying title that remains useful when the compact variant
hides supporting context. Keep subtitles factual and brief so the detail view
can be scanned quickly.

<DoDonts

      "Use one short supporting fact, such as “Staff Designer”, as the subtitle",
    ],
  }}
  dont={{

    guidelines: [
      "Don't use a generic title such as “Person” and depend on the subtitle for identity",

### Behavior

- WHEN `variant="detail"` → THEN the title, subtitle, visible tags, and selected actions can render.
- WHEN `variant="compact"` → THEN the avatar and title remain visible while the subtitle, tags, and actions stay hidden.
- WHEN `variant="dot"` → THEN the scaled avatar becomes the visible node while text remains visually hidden.
- WHEN `hoverCard={true}` and compact or dot content is hidden → THEN hovering reveals string title/subtitle values and visible tag metadata in an `F0Card`; non-string title/subtitle content is not forwarded to the card.
- WHEN `loading={true}` → THEN skeletons replace node content and the hover card stays disabled.
- WHEN `visibleTagTypes` is provided → THEN tags outside the allowed columns are omitted from both the node and hover card.
- WHEN `state="selected"`, `variant="detail"`, and `actions` are provided → THEN `NodeToolbar` displays the actions above the node.
- WHEN `hasChildren={true}` → THEN `aria-expanded` reflects `expanded`, Arrow Right requests expansion, and Arrow Left requests collapse.

**Hidden detail**

Compact and dot nodes can reveal hidden information on hover or keyboard focus.
Pressing Escape dismisses the card without moving focus away from the node.

## Accessibility

F0GraphNode renders `role="treeitem"` and must remain inside a `role="tree"` ancestor. `F0Graph` provides this container; custom ReactFlow canvases must provide the equivalent semantics.

### Placing the `role="tree"` container

A `role="group"` wrapper is not a substitute for the tree. axe walks up from the treeitem and, on meeting a `group`, stops accepting `group` and keeps looking for a real `tree` above it, so a lone `group` fails `aria-required-parent`.

ReactFlow hardcodes `role="application"` on its root element, after its props spread, so it cannot be overridden. Wrapping `<ReactFlow>` in the `role="tree"` container therefore gives that tree an `application` child, which fails `aria-required-children` — and `aria-owns` does not rescue it, because the rule reads what the tree contains, not only what it owns. Put the container inside the node type, wrapping the treeitem, or keep it out of the ReactFlow subtree entirely. The `WithToolbar` story above shows the first shape.

### Screen reader behavior

- `aria-expanded` is present only when `hasChildren` is true.
- `aria-level`, `aria-setsize`, and `aria-posinset` describe the node's position in the tree.
- `aria-selected` reflects the selected visual state.
- `aria-owns` can connect a node to descendant treeitem ids when the rendered DOM is not nested.
- Use one `tabIndex={0}` node per graph and `tabIndex={-1}` for the remaining nodes so keyboard focus follows the graph's roving tab-index model.
- `loading` sets `aria-busy="true"` and preserves a string title as the treeitem's accessible name. Provide `ariaLabel` when a loading node's title is not a string.
