# Filter picker

Filter picker narrows a collection down to the rows a person cares about. It owns
the whole filtering surface: a trigger that opens the filter form, optional
presets, and a chips row summarising what is currently applied.

Filters are declared as data (a `FiltersDefinition`), so the picker renders the
right control per filter type instead of each screen assembling its own.

## Anatomy

<Canvas of={F0FilterPickerStories.Default} meta={F0FilterPickerStories} />

Three parts, in reading order: the **Filters** trigger (icon-only button, with a
dot when anything is applied), the **presets** row, and the **chips** row with a
Clear action. Opening the trigger reveals a two-pane form, filter list on the
left and the selected filter's options on the right.

| Prop                | Type                                        | Default  | Description                                                                    |
| ------------------- | ------------------------------------------- | -------- | ------------------------------------------------------------------------------ |
| `value`             | `FiltersState<Definition>`                  | —        | Currently applied filters. Required.                                           |
| `onChange`          | `(value: FiltersState<Definition>) => void` | —        | Fired when the person applies or clears filters. Required.                     |
| `filters`           | `Definition`                                | —        | The available filters and their configuration.                                 |
| `presets`           | `PresetsDefinition<Definition>`             | —        | Predefined filter combinations offered above the chips row.                    |
| `presetsLoading`    | `boolean`                                   | `false`  | Renders the presets row in a loading state.                                    |
| `mode`              | `FiltersMode`                               | —        | Layout mode for the filter surface.                                            |
| `onOpenChange`      | `(isOpen: boolean) => void`                 | —        | Fired when the filter form opens or closes.                                    |
| `displayCounter`    | `boolean`                                   | `false`  | Shows a count of applied filters.                                              |
| `resultCount`       | `number`                                    | —        | Total matching items, rendered as an "N results for:" prefix on the chips row. |
| `selectedPresetId`  | `string`                                    | —        | Selected preset id. With `onSelectPreset`, selection becomes identity-based.   |
| `onSelectPreset`    | `(presetId: string) => void`                | —        | Selects a preset by id. Enables identity-based selection.                      |
| `editablePresetIds` | `string[]`                                  | —        | Presets that can be edited or deleted (user-created ones).                     |
| `onEditPreset`      | `(presetId: string) => void`                | —        | Opens the edit flow for a preset.                                              |
| `presetActionState` | `"save" \| "none"`                          | `"none"` | Whether to show the dashed "Save view" chip.                                   |
| `onPresetAction`    | `() => void`                                | —        | Opens the preset create/update dialog.                                         |
| `children`          | `ReactNode`                                 | —        | Extra content rendered inside the filter surface.                              |

### Composition

Used as a single element, `F0FilterPicker` renders the default layout: controls,
presets, then chips. The pattern module also exports each part separately, for a
screen that needs a different arrangement (chips above the controls, say).

```tsx
import * as F0FilterPicker from "@/patterns/F0FilterPicker"

export const CustomLayout = () => (
  <F0FilterPicker.Root filters={filters} value={value} onChange={onChange}>
    <F0FilterPicker.Controls />
    <F0FilterPicker.Presets />
    <F0FilterPicker.ChipsList />
  </F0FilterPicker.Root>
)
```

The parts are reachable inside F0 only: the package entry point exports the
`F0FilterPicker` element and the filter types, not the individual parts. Nothing
in the repo composes them today, so treat this as the escape hatch it is. A
filter surface that looks the same on every screen is worth more than a bespoke
one.

## Presets

Presets are predefined filter combinations. For example, with a department
filter, a preset can show only the Engineering team.

<Canvas of={F0FilterPickerStories.WithPresets} meta={F0FilterPickerStories} />

## Setting Filters, presets and use them in the data source

To enable filters in your data collection component, supply the filter attribute
in the source prop, for the presets use the presets attribute, remember you need
to define the filters first and apply a preset over an existing filter.

Example:

```tsx
const FiltersDefinition: FiltersDefinition<typeof mockUsers> = {
  department: {
    type: "in",
    label: "Department",
    options: {
      options: [
        { value: "Engineering", label: "Engineering" },
        { value: "Marketing", label: "Marketing" },
        // …
      ],
    },
  },
  search: { type: "search", label: "Search" },
  date: { type: "date", label: "Date" },
} as const

const presets: PresetsDefinition<typeof filters> = [
  { label: "Engineering Only", filter: { department: ["Engineering"] } },
  { label: "Product Team", filter: { department: ["Product"] } },
]
```

## Usage

### Default layout

The default layout is a single component that renders the filters, presets and
chips list.

```tsx
<F0FilterPicker
  value={value}
  filters={filterDefinition}
  presets={presets}
  onChange={handleChange}
>
  Optional children content
</F0FilterPicker>
```

## Guidelines

### When to use

- A collection has more rows than a person can scan, and they need to narrow it
  by attributes: department, status, date range, owner.
- The same collection is read in different ways by different people, and those
  views are worth saving as presets.
- Filtering has to survive a reload or be shareable as a URL. The
  `WithUrlSerialization` story shows the `serializeFilters` /
  `deserializeFilters` round trip.

### When not to use

- **One filter, always visible.** A single status toggle or a lone search box
  does not need a filter surface. Use `F0SearchInput` or a
  `F0ButtonToggleGroup` inline.
- **Choosing one thing rather than narrowing many.** That is a select, not a
  filter. Use `F0Select`.
- **Inside a modal or a sidebar with no room for a popover.** Use
  `F0FilterPickerContent`, which renders the same two-pane form without the
  popover wrapper.
- **Filtering a collection you already render with `OneDataCollection`.** Pass
  `filters` to its data source instead; it mounts and wires the picker for you.

### Best practices

<DoDonts
  do={{

## Accessibility

The **Filters** trigger is an icon-only button, so it carries a translated
accessible name from `i18n.filters.label` rather than relying on the icon alone.
While the form is open the trigger points at it with `aria-controls`.

When filters are applied, a dot appears on the trigger. Colour is not the only
signal: the trigger is also described, via `aria-describedby`, by a visually
hidden summary of what is currently applied, so a screen reader announces the
applied filters rather than just "Filters, button".

Each chip in the applied row is removable, and the row's Clear action is labelled
from `i18n.actions.clear`. Every string in the surface comes from the i18n
provider, so nothing is hardcoded in English.

Each chip's remove button is a 24×24 target with a 24px offset from the chip's
own label button, meeting WCAG 2.2 SC 2.5.8 (target size).

Axe runs blocking on every story in this file (`a11y: { test: "error" }`), so a
regression in any of the above fails CI rather than being filed as a warning.
Stories that start with filters already applied wait for the chips row to settle
before the scan: chips arrive asynchronously as `in` filters resolve their option
labels, and each one animates in, so an early scan would measure a chip
mid-flight rather than its resting hit area.

## Filter Types

### In

The `in` filter is used to filter the data by a list of values.

#### Options

- `options`:
  `() => (Promise<{value: string, label: T}[]> | {value: string, label: T}[])`
  The list of options to filter the data. NOTE: By default the options are not
  cached so each time the filter is opened, the options will be loaded again
  (and to generate the chip label the options will be loaded again) You can
  cache it by yourself or use the `cache` option.
- `cache?`: `boolean` Whether to cache the options.

```tsx
const filters: FiltersDefinition<typeof mockUsers> = {
  department: {
    type: "in",
    label: "Department",
    options: {
      options: [
        { value: "Engineering", label: "Engineering" },
        { value: "Marketing", label: "Marketing" },
        // ...
      ],
      cache: true,
    },
  },
}
```

This returns an array of values.

### Date

The `date` filter is used to filter the data by a date value. The filter allows
limit user select to a min and max date.

#### Options

- `minDate?`: The minimum date that the user can select.
- `maxDate?`: The maximum date that the user can select.
- `mode?`: The mode of the date filter, can be `single` (default), `range` or
  `multiple`.
- `view?`: The view of the date filter, can be `day` (default), `week`, `month`
  or `year`.

```tsx
const filters: FiltersDefinition<typeof mockUsers> = {
  date: {
    type: "date",
    label: "Date",
    options: {
      minDate: new Date("2021-01-01"),
      maxDate: new Date("2021-12-31"),
      mode: "range",
      view: "day",
    },
  },
}
```

### Search

The `search` filter is used to filter the data by a search query.

```tsx
const filters: FiltersDefinition<typeof mockUsers> = {
  search: { type: "search", label: "Search" },
}
```

### Number

The `number` filter is used to filter the data by a number value. The filter
allows limit user select to a min and max number.

#### Options

- `min?`: The minimum number that the user can select.
- `max?`: The maximum number that the user can select.
- `modes?`: The modes of the number filter, can be `range` (default) or/and
  `single`.
- `openCloseToggle?`: Whether to show a toggle to open and close the range.
  Default is `false`.

```tsx
const filters: FiltersDefinition<typeof mockUsers> = {
  number: {
    type: "number",
    label: "Number",
    options: {
      min: 0,
      max: 100,
      openCloseToggle: true,
    },
  },
}
```

The filter returns a object with the following properties:

- `mode`: The mode of the number filter, can be `range` or `single`.
- `from`: The minimum number that the user can select.
- `to`: The maximum number that the user can select.
- `closed`: Whether the range is closed or open
  [Mathematical definition of open and close intervals](<https://en.wikipedia.org/wiki/Interval_(mathematics)#Definitions_and_terminology>).

```tsx
{
  mode: "single",
  value: 100,
}
// or
{
  mode: "range",
  from: {
    value: 100,
    closed: true,
  },
  to: {
    value: 100,
    closed: false,
  },
} // Means >= 0 and < 100
// or
{
  mode: "range",
  from: {
    value: 0,
    closed: false,
  },
  to: {
    value: undefined,
    closed: true,
  },
} // Means > 0
```

## Adding a new filter type

FiltersPicker provides a modular system to add new filter types easily.

To add a new filter type follow these steps:

1. Create a folder in the `F0FilterPicker/filters/FilterTypes` folder. (e.g.
   `F0FilterPicker/filters/FilterTypes/myFilterType`)

2. Create a `index.tsx` file in the new folder and export the filter type
   definition.

```tsx
export const myFilter: FilterTypeDefinition<number> = {
  // The empty value is the value returned when the filter is not set
  emptyValue: 0,
  // The render function is used to render the filter form that allows the user to set the filter value
  render: (props) => <MyFilterForm {...props} />,
  // The isEmpty function is used to check if the filter is empty
  isEmpty: (value) => value === undefined || value === 0,
  // The chipLabel function is used to label the filter in the chip
  chipLabel: (value) => value.toString() ?? "-",
}

export type MyFilterDefinition = BaseFilterDefinition<"myFilter">
```

3. Import the new filter type in the `F0FilterPicker/filters/filters.ts` file
   and add it to the `filterTypes` object.

```tsx
import { myFilter, MyFilterDefinition } from "./FilterTypes/myFilter"

export const filterTypes = {
  in: inFilter,
  search: searchFilter,
  date: dateFilter,
  ...
  myFilter: myFilter,
} as const

```

4. Add the new filter type to the `FilterDefinitionsByType` type.

```tsx
export type FilterDefinitionsByType = {
  ...
  myFilter: MyFilterDefinition,
}
```

5. Add the new filter type to the `filters` object.

```tsx
const filters: FiltersDefinition<typeof mockUsers> = {
  myFilter: myFilter,
}
```

5. Add the new filter type Value to the `FilterValue` type.

```tsx
export type FilterValue<T extends FilterDefinition> =
  T extends InFilterDefinition<infer U>
    ? U[]
    : T extends SearchFilterDefinition
      ? string
      : T extends DateFilterDefinition
        ? Date
        : T extends MyFilterDefinition
          ? number
          : never
```
