### Report filters

Report filters are one applied state shared by every participating item. Pass `filtersValue` with `onFiltersChange` to own that state — for example to hydrate a saved report and persist each committed change — or pass only `defaultFilters` to let the dashboard own it.

```tsx
const [filtersValue, setFiltersValue] = useState<FiltersState<typeof filters>>(
  savedReport.filters
)

<F0AnalyticsDashboard
  filters={filters}
  filtersValue={filtersValue}
  onFiltersChange={setFiltersValue}
  items={items}
/>
```

- WHEN `filtersValue` is provided → THEN the dashboard is controlled and waits for the parent to pass each committed value back.
- WHEN only `defaultFilters` is provided → THEN the dashboard owns subsequent committed filter state.
- WHEN Apply, Clear, chip removal, or a preset commits a change → THEN `onFiltersChange` receives the next applied state and participating items refetch with it.
- WHEN the picker closes without applying → THEN temporary selections are discarded.
- WHEN an item sets `useDashboardFilters=false` → THEN that item fetches with an empty filter object.
- WHEN `items` is empty → THEN the filter bar remains usable without a grid item fetch.

### Usage examples

Every example keeps the applied value visible above the report, so committed changes can be reviewed without inspecting component internals.

**Empty controlled state**

Start from an empty saved value. There are no applied chips or filter counter until a reviewer commits the first report filter.

<Canvas of={Stories.ReportFiltersEmpty} />

**Pre-applied and commit lifecycle**

Start from a saved Department filter. Draft changes roll back on dismiss; Apply, Clear, chip removal, and presets update the visible parent state.

<Canvas of={Stories.ReportFiltersPreApplied} />

**Scalar values**

Review search text, one selected option, a single date, and a single number.

<Canvas of={Stories.ReportFilterScalarValues} />

**Collection and range values**

Review multiple selected options, a date range, and a numeric range. Boolean and valueless filters are not native `OneFilterPicker` filter types, and are intentionally not represented as supported dashboard controls.

**With dashboard export**

The export control uses the applied report filter value for participating
items. Items with `useDashboardFilters=false` are exported with an empty filter

### Screen reader behavior

- The filter trigger keeps the stable name "Filters"; applied filter labels are exposed as its accessible description, while a visible counter shows how many report filters are active.
- The filter popover has a dialog name, and filter options expose native checkbox semantics.
- Applied filter removal buttons keep the stable name "Close"; the filter label and selected value are exposed as their accessible descriptions.
