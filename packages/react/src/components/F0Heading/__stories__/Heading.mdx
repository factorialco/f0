# F0Heading

Renders a page, section, or card title on the shared typographic scale, keeping visual size (`variant`) independent from document structure (`as`). For body copy, descriptions, and labels use `F0Text`; for the header of an entity page (employee, team, company) use `ResourceHeader`; for a titled section inside a page or form use `SectionHeader` — it already handles description, help center link, separator, and action.

`variant` is visual only — the rendered element comes from `as`. When `as` is omitted, the tag falls back to the variant default: `heading-large` renders `<h1>` and `heading` renders `<h2>`. `align`, `ellipsis`, `noEllipsisTooltip`, and `markdown` are inherited from the underlying `Text` primitive.

## Guidelines

### Design best practices

**When to use**

- Use `heading` for section and panel titles inside a page — the default for most cases (for example "Time off requests" above a list of requests)
- Use `heading-large` for the primary title of a page or dashboard view, at the top of the content area
- Use `F0Heading` when you need a title in a surface that no higher-level component covers: a custom card, an empty state, a side panel, a step in a wizard

**When not to use**

- Body copy, descriptions, field labels, or table cell text — use `F0Text`
- The header of an entity page (employee, team, company) — use `ResourceHeader`, which handles avatar, metadata, status, and actions
- A section header inside a page or form — use `SectionHeader`, which handles description, help center link, separator, and action button
- A short status or count next to a title (for example "3 pending") — use `F0TagStatus` alongside the heading, not a second heading

**Hierarchy and semantics**

- `heading-large` appears once per view; every title below it uses `heading`
- Set `as` explicitly whenever the heading has a fixed place in the page outline — the visual variant does not follow the outline for you
- Never use alignment, casing, or an extra `heading-large` to fake a level that the outline does not have

### Content best practices

- Keep headings short and descriptive — one line at the container width is the target
- Use sentence case: "Time off requests", not "Time Off Requests"
- Name the content, don't describe the action: "Team members", not "Manage your team members"
- Avoid punctuation at the end of headings
  - **Correct:** "Team members", "Monthly payroll report"
  - **Incorrect:** "Team members:", "Monthly payroll report."

### Behavior

**Alignment**

`align` controls only the horizontal alignment of the text inside the element. The heading still fills the width of its container, so alignment never changes the layout around it. It defaults to `left`.

<Canvas of={Stories.HeadingAlignment} />

- Keep the default `left` for page and section titles — it matches the reading order of the content below
- Use `center` only on surfaces that are centered as a whole: empty states, onboarding cards, centered dialogs
- Avoid `right` in left-to-right layouts; a right-aligned title detaches from the content it introduces

**Ellipsis truncation**

With `ellipsis={true}` the heading truncates to a single line with `…`; pass a number (`ellipsis={2}`) to allow that many lines before truncating. The heading must sit in a container with a constrained width for truncation to happen at all. When the text is actually truncated, a tooltip with the full text is rendered automatically — the tooltip always shows the plain-text version, with any markdown stripped.

## Accessibility

- Set `as` to the heading level that matches the position in the page outline — screen reader users navigate by heading level, and `variant` has no effect on it
- A view has exactly one `h1`. Use `as="h1"` only for the top-level page title, and remember that `heading-large` already defaults to `h1`
- Do not skip levels (`h1` to `h3`) — the jump reads as a missing section in the heading list
- Do not pass `noEllipsisTooltip` on a truncated heading: the automatic tooltip is the only way to read the full title once the text is cut off
- Truncated text is still exposed in full to assistive technology, because the element keeps the complete `content` string in the DOM
