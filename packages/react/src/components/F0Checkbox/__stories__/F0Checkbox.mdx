# Checkbox

Captures one or more independent selections as a form value — picking employees
from a list, opting into a notification, or summarising a partially selected
group through the indeterminate state. For picking exactly one option from many
use `F0Select`; for a small set of mutually exclusive choices shown side by side
use `F0ButtonToggleGroup`.

## Anatomy

A checkbox is composed of the selection control itself plus a `title` label.
Always provide a meaningful `title` so the control is clearly labelled, both
visually and for assistive technology. The component is controlled — provide
`checked` and update it from the `onCheckedChange` callback.

## States

### Checked

Set the `checked` prop to reflect the current selection. Because the checkbox is
controlled, you are responsible for storing the value and updating it whenever
the `onCheckedChange` callback fires.

<Canvas of={CheckboxStories.Checked} />

### Indeterminate

A checkbox can be in an indeterminate state, which is useful for indicating that
only some options within a group are selected. It is controlled through the
`indeterminate` prop and is purely visual — it swaps the check glyph for a minus
while the underlying checked value stays whatever `checked` reports.

<Canvas of={CheckboxStories.Indeterminate} />

### Disabled

Disable interaction by setting the `disabled` prop. A disabled checkbox keeps
its current visual state but cannot be toggled, and it is skipped by keyboard
navigation.

<Canvas of={CheckboxStories.Disabled} />

### Content best practices

- Label the outcome of checking, never the outcome of leaving it unchecked
  - **Correct:** "Include probation period in the contract"
  - **Incorrect:** "Do not exclude the probation period"
- Sentence case, no trailing period
  - **Correct:** "Notify the employee by email"
  - **Incorrect:** "Notify The Employee By Email."
- Name the thing the row represents instead of describing the act of selecting
  - **Correct:** "Ana Ruiz"
  - **Incorrect:** "Select this employee"
- Say what a select-all covers, because it only ever spans what is loaded
  - **Correct:** "Select all employees on this page"
  - **Incorrect:** "Select all"

### Behavior

- The checkbox is always controlled: it renders whatever `checked` says and
  never keeps internal state. If `onCheckedChange` does not write the value
  back, the control appears frozen.
- `indeterminate` and `checked` are independent. `indeterminate` only changes
  the glyph, so a parent checkbox that is indeterminate still reports its own
  `checked` value to the form.
- `presentational` sets `tabIndex={-1}`, which removes the control from the tab
  order but leaves the click handler intact. Only use it inside a row or card
  that is itself focusable and performs the toggle.
- `stopPropagation` stops the click event from reaching parent handlers. Use it
  when a checkbox sits inside a clickable row that must not also react to the
  toggle.
- `name` falls back to the generated id when it is not provided, so pass an
  explicit `name` for checkboxes submitted as part of a native form.

### Screen reader behavior

- `title` is forwarded as `aria-label`, so the accessible name survives
  `hideLabel` — the visible label is removed but the control stays named. Never
  render the checkbox without a `title`; there is no other source for its name.
- `indeterminate` is visual only. `aria-checked` still reflects the boolean
  `checked`, so the control is announced as checked or unchecked and never as
  "mixed". A select-all header must therefore carry the partial state in its own
  copy or count (e.g. "3 of 24 selected").
- `required` renders only the red asterisk next to the label. It is not
  forwarded to the control, so there is no `aria-required` and no native
  constraint validation — the form must enforce the rule and surface the error.
- `presentational` keeps the checkbox in the accessibility tree while removing
  it from the tab order. The focusable ancestor that owns the toggle must expose
  the selected state itself, otherwise the state becomes unreachable by
  keyboard.
- `disabled` uses native disabled semantics: the control leaves the tab order
  and is announced as unavailable.
- `stopPropagation` only affects the click event. It changes nothing that is
  announced.
