# Select

Selects one or more values from static options or a data source. Use the
standard field variant in forms and the inline variant for compact, editable
values embedded in desktop rows.

### Content best practices

- Keep option labels short and parallel
  - **Correct:** "Owner", "Editor", "Viewer"
  - **Incorrect:** "This person can only view the policy"
- Use descriptions for extra capability detail rather than lengthening the label
- Name actions with an explicit verb and object
  - **Correct:** "Remove access"
  - **Incorrect:** "Remove"

### Behavior

- WHEN <code>variant="inline"</code> → THEN the required <code>label</code> prefixes the trigger's accessible name, followed by its selected label or placeholder, and is not rendered visually.
- WHEN <code>variant="inline"</code> → THEN selection is single and non-clearable, options are static Dropdown rows without Select metadata or tags, and custom triggers plus field-only search, data-source, validation, list, preview, and apply props are unavailable.
- WHEN the inline trigger opens → THEN the existing Dropdown renders a content-sized menu and owns its popup styling, focus management, and keyboard behavior.
- WHEN an inline option is selected → THEN its value, original item, and option are reported through the standard callbacks; Dropdown exposes its checked state and marks it with a trailing check without consuming the option's leading icon or avatar slot.
- WHEN <code>actions</code> are provided → THEN field selects keep their existing button footer, while inline selects append the actions to Dropdown after one separator.
- WHEN an inline action has an <code>icon</code>, <code>variant="critical"</code>, or <code>disabled</code> → THEN those values map directly to Dropdown's icon, critical, and disabled item behavior.
- WHEN the inline menu closes → THEN Dropdown restores focus to its trigger.
- <code>T</code> is the string value type and <code>R</code> is the original
  record type, defaulting to <code>unknown</code>. A literal union such as
  <code>"owner" | "editor" | "viewer"</code> keeps <code>value</code>, option
  values, and <code>onChange</code> aligned. Single selection calls
  <code>
    onChange(value: T, originalItem?: R, option?: F0SelectItemObject&lt;T,
    R&gt;)
  </code>
  . Multiple selection calls
  <code>
    onChange(value: T[], originalItems: R[], options: F0SelectItemObject&lt;T,
    R&gt;[])
  </code>
  .

## Accessibility

### Field keyboard interaction

- The field trigger is a combobox. <kbd>Enter</kbd>, <kbd>Space</kbd>, or an arrow key opens its listbox.
- <kbd>Arrow up</kbd> and <kbd>Arrow down</kbd> move through options;
  <kbd>Enter</kbd> selects the focused option.
- <kbd>Escape</kbd> closes the listbox and restores focus to the field trigger.
- Searchable fields move focus into their search input while keeping listbox keyboard navigation available.

### Field screen reader behavior

- The visible or visually hidden field label names a <code>combobox</code> trigger.
- The popup exposes a <code>listbox</code> with <code>option</code> children and the current selected state.
- Validation status, hints, and errors remain associated with the field control.

### Inline screen reader behavior

- The trigger is a labeled button with <code>aria-haspopup="menu"</code> and <code>aria-expanded</code>. Its accessible name combines the required <code>label</code> with the current option label or placeholder. Make the label specific to the subject in repeated rows—for example "Access level for Jane Doe".
- Dropdown exposes options as <code>menuitemradio</code> elements with <code>aria-checked</code>, while actions remain <code>menuitem</code> elements.
- Option and action labels provide each Dropdown item's accessible name.
- The inline chevron is decorative and hidden from the accessibility tree.
- Disabled triggers use the native <code>disabled</code> state.
