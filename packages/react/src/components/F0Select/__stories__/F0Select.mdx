# Select

Selects one or more values from static options or a data source. Use the
standard field variant in forms and the inline variant for compact, editable
values embedded in desktop rows.

### Content best practices

- Keep option labels short and parallel
  - **Correct:** "Owner", "Editor", "Viewer"
  - **Incorrect:** "This person can only view the policy"
- Use descriptions for extra capability detail rather than lengthening the label
- Name footer actions with an explicit verb and object
  - **Correct:** "Remove access"
  - **Incorrect:** "Remove"

### Behavior

- WHEN <code>variant="inline"</code> → THEN the required <code>label</code> becomes the trigger's accessible name and is not rendered visually.
- WHEN <code>variant="inline"</code> → THEN the trigger uses the compact borderless presentation while the popup reuses the field variant's option rows, selection indicator, and action footer.
- WHEN <code>variant="inline"</code> → THEN selection is single and non-clearable, custom triggers and field-only state props are unavailable, and the popup fits its content by default.
- WHEN <code>fitContentWidth=false</code> is explicit → THEN the standard 20rem popup minimum overrides the inline default.
- WHEN an option has a <code>description</code> → THEN its popup row is 64px high; otherwise it remains 32px high.
- WHEN an option defines <code>selectedLabel</code> → THEN the trigger displays it while the popup row keeps <code>label</code>.
- WHEN <code>actions</code> are provided → THEN the existing action footer renders below the option list.
- WHEN the inline popup closes → THEN focus returns to its trigger.
- <code>T</code> is the string value type and <code>R</code> is the original
  record type, defaulting to <code>unknown</code>. A literal union such as
  <code>"owner" | "editor" | "viewer"</code> keeps <code>value</code>, option
  values, and <code>onChange</code> aligned. Single selection calls
  <code>
    onChange(value: T, originalItem?: R, option?: F0SelectItemObject&lt;T,
    R&gt;)
  </code>
  . Multiple selection calls
  <code>
    onChange(value: T[], originalItems: R[], options: F0SelectItemObject&lt;T,
    R&gt;[])
  </code>
  .

### Screen reader behavior

- The trigger exposes <code>role="combobox"</code>, <code>aria-expanded</code>, and <code>aria-controls</code>; popup options are announced within a listbox.
- Inline <code>label</code> text is applied as <code>aria-label</code>. Make it specific to the controlled value and, in repeated rows, to the subject—for example "Access level for Jane Doe".
- The inline chevron is decorative and hidden from the accessibility tree.
- Disabled triggers use the native <code>disabled</code> state.
