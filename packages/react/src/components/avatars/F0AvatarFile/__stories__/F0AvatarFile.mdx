# AvatarFile

The avatar for a file or document.

---

## Overview

### Purpose

- Represent a file or document at a glance
- Communicate the kind of file through a short type label derived from its type

### Anatomy

A file avatar is square and shows a short type label (`PDF`, `XLS`, `IMG`, …)
derived from the file's MIME type, falling back to its extension, so the file
kind is recognizable without opening it. It is available in sizes `xs`–`lg`.

## Guidelines

### Design best practices

#### When to use

- The entity is always a file or document
- File lists, attachments, upload previews

#### When NOT to use

- The entity type is dynamic: use `F0Avatar`
- The item is not a file: use the matching `F0Avatar*` component

## Accessibility

The label inside the avatar (`PDF`, `XLS`, …) is real text, so it is read out
as-is. It names the file **kind**, never the file itself — the file name has to
come from the surrounding row or caption.

- Keep the file name as visible text next to the avatar. On its own, `PDF` tells
  a screen-reader user nothing about which document this is.
- Don't lean on `aria-label` to supply the name. The avatar root carries no
  `role`, so a label on it is an ARIA-prohibited attribute and assistive
  technology is not required to honour it — the visible text is what works.
