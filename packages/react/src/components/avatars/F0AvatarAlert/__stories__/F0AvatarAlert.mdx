# AvatarAlert

An avatar-sized status indicator that signals a state through an icon and color.

---

## Overview

### Purpose

Represent a specific, meaningful status of an item — critical, warning, info or
positive.

### Anatomy

An alert avatar is square and pairs a status icon with a matching semantic
color, both driven by the `type` prop: `critical`, `warning`, `info` or
`positive`. It is available in sizes `sm`–`lg`.

## Guidelines

### Design best practices

#### When to use

- Flagging the status or severity of an item where an avatar-sized marker fits

#### When NOT to use

- As a generic attention-grabber or decoration — reserve it for a genuine
  status; overusing it dilutes the signal
- Representing an entity (person, team, …): use `F0Avatar` or the matching
  `F0Avatar*` component
- Inline or text-level status: use a Badge or Tag instead

## Accessibility

The status has to be available as text. This marker conveys it with an icon and a
color only, so whatever it flags must also be named in the surrounding content —
a row label, a heading, an error message.

### Known limitation: `role="alert"` is hardcoded

Every instance renders `role="alert"`, which makes it an **assertive live
region** that interrupts a screen reader whenever it appears. `aria-label` is
optional, so by default the region also has no accessible name. That is wrong for
a presentational marker, and it is not something a consumer can turn off today.

Two consequences worth knowing while it stands:

- **Inside a container that already announces itself, this marker is
  redundant and can override the container's politeness.** `F0Alert` and `F0Toast`
  both set their own `role`/`aria-live` from the variant, so a non-urgent one
  (`F0Alert` `info`, `F0Toast` `success`) declares a polite region and then nests
  this assertive one inside it. Don't add another `aria-live` wrapper on top.
- **Standalone, it announces nothing useful.** With no label there is nothing to
  read out; with a label it interrupts to say something the adjacent text already
  says.

Until this is fixed, treat the marker as decorative and put the meaning in text.
Don't reach for `aria-label` to compensate: the underlying role is the problem,
and labelling it turns a silent interruption into a duplicate one.
