# Card

Summarises a single record — an employee, a candidate, a document, a project, a
board item — as a self-contained surface with an avatar, a title, a description,
metadata rows, an optional image and a footer of actions. For a filterable,
paginated collection of records use `OneDataCollection` with its card
visualization; for page-level or section-level messaging use `F0Alert`; for a
free-form panel with custom layout use `Card` from `@/ui/Card`.

## Anatomy

<Canvas of={Stories.Default} />

<Controls of={Stories.Default} />

A card renders its regions in a fixed order, and each one is optional except the
header:

- **Image band** — shown when `image` is set. Sits flush with the card edges and
  hosts the options cluster as an overlay.
- **Header** — `avatar` plus `title` and `description`. The description is
  clamped to 3 lines (2 when `compact`).
- **Options cluster** — the `⋯` dropdown (`otherActions`), the selection
  checkbox (`selectable`) and the bookmark toggle (`bookmark`). It sits at the
  top-right of the header, or over the image when `image` is set.
- **Metadata rows** — one row per `metadata` entry: a tooltipped icon plus a
  value rendered by the shared value-display renderers (text, date, amount,
  status, tag, tagList, avatarList, progressBar, file, folder…).
- **Children slot** — free-form content between the metadata and the footer.
- **Footer** — built from `primaryAction` and `secondaryActions`, separated by a
  top border.

### Content best practices

- **Title**: the record's own name, sentence case, no period. Never the name of
  the concept the card represents
  - **Correct:** "Marta Ruiz", "Q3 payroll closing", "Employment contract.pdf"
  - **Incorrect:** "Employee card", "Payroll", "Document"
- **Description**: one line of context that the title does not already give
  - **Correct:** "Design Engineer · Barcelona", "Closes 31 Oct · 214 employees"
  - **Incorrect:** "Marta Ruiz", "This is a card about an employee"
- **Metadata label**: the tooltip on the icon, so it must name the field, not
  repeat the value
  - **Correct:** `label: "Start date"` with `value: "3 May 2024"`
  - **Incorrect:** `label: "3 May 2024"`
- **Primary action label**: verb-first, no articles
  - **Correct:** "Approve", "Refer", "Request signature"
  - **Incorrect:** "OK", "Action", "Click to approve"
- **Secondary link label**: describes the destination
  - **Correct:** "View request", "See all payslips"
  - **Incorrect:** "Click here", "More"
- **Bookmark label**: names the object being saved, because the button is
  icon-only
  - **Correct:** `label: "Save candidate"`
  - **Incorrect:** omitting it when `title` alone reads as a person's name

### Behavior

- The card body is clickable as a whole only when `link` or `onClick` is set.
  Without either, it keeps the default cursor and the header gets no
  `role="button"`.
- `link` renders a full-card overlay link, so the title, the description, the
  metadata rows and the empty space all navigate — not just the title.
- The footer sits above the overlay link and stops click propagation. Clicking
  anywhere in the footer band never navigates the card; only its own buttons or
  link act.
- The children slot also stops propagation. Pointer events are re-enabled for
  `a`, `button`, `input`, `select`, `textarea`, `[role="button"]` and
  `[tabindex]` inside it, so interactive children keep working inside a linked
  card.
- Metadata clicks bubble up and navigate the card, except when the target is an
  `a[href]`, a form field or an `aria-haspopup` trigger — so `tagList` and
  `avatarList` overflow popovers keep their own behaviour.
- `alert` wraps the card in an outer element and the forwarded `ref` moves to
  that wrapper while the alert is visible. Dismissal is fully controlled: the
  `onDismiss` callback does nothing on its own until the parent flips `visible`
  (or drops `alert`).
- `imageSize` is ignored when `imageAspectRatio="video"`, and
  `blurredBackground` only applies to `contain`, `fit-width`, `fit-height` and
  `scale-down` — never to `cover`, which already fills the band.
- The options cluster fades in on hover from the `sm` breakpoint up, and stays
  visible while the dropdown is open, the card is selected or the card is
  bookmarked. On mobile it is always visible.
- On desktop, secondary actions after the first render icon-only
  (`hideLabel`); on mobile all footer buttons render full width with labels.

### Usage examples

**Actions in the footer**

A primary action plus secondary actions, separated from the body by a border.
Keep the primary as the one thing the card exists to trigger.

<Canvas of={Stories.WithActions} />

**Whole card as a link**

`link` makes the entire body navigate. Pass `title` too — it becomes the
accessible name of the overlay link.

<Canvas of={Stories.WithLink} />

```tsx
<F0Card
  title="Marta Ruiz"
  description="Design Engineer · Barcelona"
  link="/employees/marta-ruiz"

```

**Bulk selection**

`selectable` shows the checkbox; `selected` and `onSelect` are controlled by the
list that owns the selection.

<Canvas of={Stories.Selectable} />

```tsx
const [selectedIds, setSelectedIds] = useState<string[]>([])

<F0Card
  title={employee.fullName}
  selectable
  selected={selectedIds.includes(employee.id)}
  onSelect={(selected) =>
    setSelectedIds((ids) =>
      selected ? [...ids, employee.id] : ids.filter((id) => id !== employee.id)
    )
  }
/>
```

**Per-record alert with controlled dismiss**

`dismissible` renders the close button, but hiding the alert is the parent's

```tsx
  title="Marta Ruiz"

    dismissible: true,
    visible,
    onDismiss: () => setVisible(false),
  }}
/>
```

### Screen reader behavior

- With `link`, the overlay link takes `title` as its `aria-label`. A card with
  `link` and no `title` ships an unlabelled link — always pass `title`.
- The header receives `role="button"` and an `aria-label` of `title` only while
  the card is interactive (`link` or `onClick`). A display-only card stays a
  plain region.
- The three options are icon-only with hidden labels: the `⋯` trigger uses the
  translated "Other actions" label, the checkbox uses `title`, and the bookmark
  uses `bookmark.label`, then `title`, then the translated "Save". Pass
  `bookmark.label` whenever `title` alone would not say what is being saved —
  "Save candidate", not "Marta Ruiz".
- The alert strip renders `role="alert"` for `critical` and `warning`, and
  `role="status"` for `info` and `positive`, so it is announced when it appears.
  Do not wrap the card in an extra `aria-live` region.
- The alert icon is decorative — the alert `title` must carry the meaning on its
  own.
- The image uses `title` as its `alt`. There is no separate alt prop, so a card
  with an image needs a `title` that describes the record.
- `F0Card.Skeleton` sets `aria-busy="true"` and `aria-live="polite"`, so the
  transition from placeholder to loaded content is announced.
