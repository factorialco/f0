# F0SharingDialog

Combines person selection, role assignment, and an access list in one dialog for resources shared across product areas. It owns the interaction pattern while the product supplies its data source, permission rules, and mutations.

### Content best practices

- Name the resource in the title.
  - **Correct:** "Share time off policy"
  - **Incorrect:** "Share"
- Keep role labels short nouns and explain capabilities in descriptions.
  - **Correct:** "Editor" — "Can view and edit this policy"
  - **Incorrect:** "Has more permissions"

### Behavior

- WHEN no people are selected → THEN the role control stays hidden and the share action stays disabled.
- WHEN one or more people are selected → THEN an inline role control appears inside the picker and starts at <code>defaultRole</code>.
- WHEN <code>onAddPeople</code> resolves to anything except <code>false</code> → THEN the selected people and role reset.
- WHEN <code>onAddPeople</code> resolves to <code>false</code> or rejects → THEN the pending selection remains available for retry.
- WHEN the dialog closes → THEN transient selection state resets before the next opening.
- WHEN <code>canChangeRole=false</code> → THEN the role renders as read-only text; an independent remove action remains available only when <code>canRemove=true</code>.
- WHEN <code>canChangeRole=true</code> and <code>canRemove=false</code> → THEN the destructive remove action remains visible but disabled.
- WHEN <code>accesses</code> is empty → THEN the access section shows an empty message.
- WHEN <code>defaultRole</code> is missing or non-assignable → THEN the component throws a configuration error.
- WHEN an access entry references a role absent from <code>roles</code> → THEN the component throws a configuration error.

The generic parameters are <code>Person extends RecordType</code>, <code>Role extends string</code>, and <code>PersonId extends string = string</code>. <code>onAddPeople</code> receives <code>{`{ personIds: PersonId[]; people: Person[]; role: Role }`}</code>, while existing-row callbacks receive the complete typed access entry.

### Screen reader behavior

- The dialog heading supplies the dialog's accessible name and focus remains trapped while it is open.
- The people picker and new-person role selector have translated accessible labels even when their visible field labels are hidden.
- Every editable access role is labelled with the mapped person name, for example "Access level for Blake Taylor".
- Access entries use list semantics; avatar images remain supplementary to the visible person label.
- Access mutations expose a polite status message and mark the access region as busy while an update is running.
- After a successful removal, focus returns to the people picker instead of being lost with the removed row.
