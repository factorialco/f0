# F0LocationInput

`F0LocationInput` is the writable address field for forms. The user types an address, picks a suggestion, and the component emits one **structured value** (street, city, state, postal code, ISO-2 country, coordinates) so no product surface has to parse a place result again. It has two modes: a single autocomplete field, or a grouped block with the country on top and the parts below.

The component makes **no network call and ships no API key**. The consumer injects `searchPlaces` and `resolvePlace`; without them the parts are plain fields.

---

## Overview

### Anatomy

<Canvas of={Stories.Detailed} />

- **Country selector** (detailed mode only): searchable `F0Select` with flag avatars, built from the translated country list. The selected country is passed to `searchPlaces` so the provider can restrict its suggestions.
- **Address field**: a combobox. It is the whole component in simple mode and the address line in detailed mode. Typing two or more characters searches; the suggestion list opens below, matching the field's width.
- **Parts** (detailed mode only): the fields passed in `fields`, in a fixed order: address line 2, city, then state / region and postal code sharing a row.
- **Label, hint, status message**: standard input chrome. In detailed mode the message is shown once, under the group.

## Guidelines

### Design best practices

#### When to use

- The user enters a postal address that will be stored, shown on a map, or used for geofencing. The structured value keeps every consumer on the same field names.
- International audiences: the same component serves every country, with generic labels the consumer can override through `partLabels`.
- A form already has a country field: pass `fields` without `"country"` and set `defaultCountry` from your own field to scope the search.

#### When NOT to use

- Picking one of the company's existing workplaces or sites. That is a select over records, not an address entry.
- Free-form location notes ("2nd floor, ask for Ana"). Use [F0TextInput](?path=/docs/components-inputs-text-input--documentation).
- Showing a saved address read-only. Render the `formatted` string instead.
- Drawing a geofence radius or dragging a pin. This component stops at the address; put an `F0Map` next to it.

#### Simple vs detailed

Use **simple mode** when a picked suggestion is the whole job: search boxes, filters, quick "where" prompts. Use **detailed mode** whenever the user may need to correct a part, or when the address may not exist in the provider (new buildings, rural addresses, no autocomplete entitlement).

### Content best practices

- Keep the group `label` about the thing, not the action: "Office address", not "Enter address".
- Leave the address `placeholder` unset unless you have a good reason: the default asks the user to start typing.
- Part labels are generic on purpose ("State / region", "Postal code"). Override them through `partLabels` when the product knows the country ("ZIP code", "Province").
- Validation is consumer-side: the component reports `isResolved` but never blocks input.

## Behavior

### Value model

The value is `F0LocationInputValue | undefined`:

- Text parts: `addressLine1`, `addressLine2`, `city`, `state`, `postalCode`.
- `country`: lowercase ISO-2 code (`"es"`), typed as `CountryCode`.
- `formatted`: a display string. It comes from `resolvePlace` after a pick and is reassembled locally once the user edits any part.
- Resolution data: `placeId`, `latitude`, `longitude`, `timezone`. Present only while the value is exactly what the provider returned.
- `undefined` when every part is empty and no country is selected.

Every `onChange` carries `meta`:

- `source`: `"picked"` right after a suggestion resolves, `"typed"` for any manual edit.
- `isResolved`: whether `placeId` and both coordinates are still present.

### Editing invalidates the pick

Editing any part, including the country, drops `placeId`, `latitude`, `longitude` and `timezone` and emits `{ source: "typed", isResolved: false }`. The typed text is kept. Consumers that need coordinates for a typed address geocode it themselves.

### Country and search scope

`searchPlaces(query, { country })` receives the value's country, else `defaultCountry`, else the single entry of `countries`. Changing the country clears the cached suggestions. Picking a suggestion from another country updates the country selector, because the resolved value replaces the whole value.

### Without a provider

Omit `searchPlaces` and the address field is a plain text input: no combobox role, no listbox, no network. This is how a surface without the autocomplete entitlement renders the same form.

### Inside a dialog

The suggestion list portals into the surrounding centered or fullscreen `F0Dialog`, so a click on a suggestion is never read as a click outside.

## Code

```tsx
import {
  F0LocationInput,
  detailedLocationFields,
} from "@factorialco/f0-react/experimental"

;<F0LocationInput
  label="Office address"
  fields={detailedLocationFields}
  countries={["es", "pt", "fr"]}
  searchPlaces={(query, { country }) => places.autocomplete(query, country)}
  resolvePlace={(id) => places.details(id)}
  onChange={(value, meta) => {
    setAddress(value)
    if (value && !meta.isResolved) scheduleGeocode(value)
  }}
/>
```

## Accessibility

### Keyboard interaction

| Key                         | Result                                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------------------------- |
| Type two or more characters | Searches and opens the suggestion list                                                                    |
| `ArrowDown` / `ArrowUp`     | Moves the active suggestion, wrapping at both ends. `ArrowDown` on a closed list reopens the last results |
| `Enter`                     | Picks the active suggestion. With no active suggestion it keeps its form meaning                          |
| `Escape`                    | Closes the list and keeps the typed text. It does not reach the surrounding dialog                        |
| `Tab`                       | Closes the list without picking and moves on                                                              |

### Screen reader behavior

- The address field has `role="combobox"`, `aria-autocomplete="list"` and `aria-expanded`. While the list is open it points at it with `aria-controls` and at the active row with `aria-activedescendant`; focus never leaves the input.
- Suggestions are `role="option"` rows with `aria-selected`; the loading and empty rows are `role="status"`.
- In detailed mode the parts are grouped in a `fieldset` whose `legend` is the `label`, so each part is announced within its group. The group message is linked once, under the parts.
- Without `searchPlaces` the field drops the combobox role and is announced as a plain text field.
