# Switch — inline variant

`variant="inline"` is the detail-row presentation of Switch: a record that
reads as rows, where each row prints a label on the left and its value on the
right. The switch fills the value column and carries no chrome of its own.

With no `variant`, nothing changes — the default `"field"` presentation is
still what you get.

## Anatomy

An inline switch is the control inside a box the row declares. The box is the
form's 40px row height and puts the control at the same 12px inset an inline
text input puts its first glyph, so a column of mixed rows lines up. It paints
no border and no background: the row owns the surface.

<Canvas of={SwitchInlineStories.DetailRow} />
<Controls of={SwitchInlineStories.DetailRow} />

The control is live at rest. A switch is already its own editor, so the inline
variant has no read-as-text state to activate and no edit affordance to hover
for. One click commits through `onCheckedChange`, exactly as in the field
variant.

That also means two props the other inline variants take do not exist here:
`editing` and `onDismiss` are declared as `never`. A field layer can still hand
every inline component the same prop bag, and the type tells it that a toggle
has no edit mode.

## States

### Read-only

A row the viewer may see but not change is `disabled`. The switch keeps its
name and its value in the accessibility tree, so the record's state is still
announced rather than the row being skipped.

<Canvas of={SwitchInlineStories.DetailRowDisabled} />

### Visible label

The row's own label column names the field, so consumers pass `hideLabel` and
the `title` becomes the control's accessible name. Without `hideLabel` the
switch keeps its visible label, which is what a standalone use outside a row
wants.

<Canvas of={SwitchInlineStories.DetailRowWithVisibleLabel} />

### Filling the row's box

Both axes are the row's to decide. The variant fills whatever box it is given,
and centres the control in it.

<Canvas of={SwitchInlineStories.FillsTheRowBox} />

## Accessibility

- `title` is the accessible name whether or not the label is visible, so never
  leave it out in a row.
- The control keeps its 24×24 hit area from the field variant, which satisfies
  WCAG 2.2 SC 2.5.8 without relying on the spacing exception.
- A disabled row stays in the accessibility tree with its name and checked
  state, so the value is announced even where it cannot be changed.
- The row's label column is decorative once `hideLabel` is set — it repeats
  what `title` already gives the control.

## Guidelines

### When to use

- A boolean field inside a record that reads as detail rows
- A setting that takes effect the moment it is switched, with no separate save

### When not to use

- **A boolean captured as a form value**, submitted later with the rest of the
  form: use the default field variant inside the form's own layout
- **A row that needs a confirmation before the value changes**: a switch
  commits on click, so put the confirmation in the flow around it
- **Outside a detail row**: the variant assumes a 40px box and a label column
  that are not there
