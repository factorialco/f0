# F0CommandPalette

A single overlay for finding anything and acting on it, opened with `mod+K` from anywhere. It searches commands, records and destinations at once, and — for a record whose domain has registered actions — turns into that record's action list. For a search field bound to one list use `F0SearchInput`; for a decision that must be resolved before continuing use `F0Dialog`.

There is one grammar, and everything below is a piece of it:

```
[scope] › [action] › [params]
```

The **scope** is a record or a selection, the **action** is the verb, the **params** are the values that verb still needs. The palette itself never confirms anything: choosing an action hands it back to you, and your own dialog is the confirmation.

## When to use

- **A launcher.** One keystroke to reach any screen, any record, or any command in the product, without knowing where it lives in the navigation.
- **The action surface for a record.** Any place that already knows its target — a row menu's "All actions…", a bulk bar, a detail header — opens it pre-scoped via `openScoped(ref)`, so the only thing left to do is name the verb. That is what stops every module building its own action picker.
- **The one door for an assistant.** When something is a question rather than a lookup, `mod+Enter` hands the query over instead of returning "No results".

## When not to use

- **Filtering a list that is already on screen.** That is `F0SearchInput` inside the list's own toolbar. The palette is for reaching things that are _not_ in front of you.
- **A form.** Parameter levels collect a choice from a list, not free text across several fields. An action needing that should collect nothing and open its own dialog from `run`.
- **A confirmation.** The palette deliberately has no confirm level. A destructive action is kept out of the default selection and away from a bare `Enter`; the dialog you already own is what asks.
- **The only way to reach an action.** It is a shortcut, never the sole path — a reader who has never pressed `mod+K` must still get there through the UI.

## Anatomy

| Part            | What it is                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **Bar**         | The sentence being written: the search icon, the committed scope, the rendered `/` separator, the input, and the assistant button.    |
| **Scope**       | The record or selection the list is about. Plain text in the input's own type — not a tag — removable by pointer or with `Backspace`. |
| **List**        | Grouped rows. Headings are ordinary secondary text; rows of one group are always contiguous.                                          |
| **Row**         | A leading glyph or avatar, the label, an optional origin badge, and the context trailing it on the same line.                         |
| **Row actions** | Secondary actions floated over the row's right edge, revealed on hover, on the active row, and while one holds focus.                 |
| **Footer**      | The gesture that matters right now, as key-and-label pairs.                                                                           |

### Modes

| Mode                     | Reached by                                   | The list holds                                                                         |
| ------------------------ | -------------------------------------------- | -------------------------------------------------------------------------------------- |
| **Global, empty query**  | Opening it                                   | `recent`, then `actions` as "Suggestions"                                              |
| **Global, with a query** | Typing                                       | Ranked `actions`, records from every provider, ranked `navigation`, then the assistant |
| **Scoped**               | `/` or `→` on a record, or `openScoped(ref)` | That record's actions — suggested first, blocked last                                  |
| **Parameter**            | Choosing an action with `params`             | That step's options                                                                    |

### Keyboard

| Key         | What it does                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------- |
| `mod+K`     | Opens and closes the palette                                                                                         |
| `↑` `↓`     | Moves the selection                                                                                                  |
| `Enter`     | Runs the active row. On a record it **navigates** and never executes                                                 |
| `/`         | Commits the highlighted record as the scope. An ordinary character everywhere else, so slashes in names stay typable |
| `→`         | The same gesture, from the end of the query only                                                                     |
| `Tab`       | Reaches the active row's own actions, then cycles the selection when it has none                                     |
| `Backspace` | On an empty query, walks back one level: parameter → action → scope → nothing                                        |
| `Escape`    | Pops one level, and closes only when there is nothing left to pop                                                    |
| `mod+Enter` | Hands the query and the scope to the assistant                                                                       |

## Guidelines

### Design best practices

- **Verb-first action labels.** "Lock screen", not "Screen locking". The row beside it already names the target, so the label only has to carry the verb.
- **A second line has to earn it.** Leave `description` out when it repeats the label in a quieter grey — "Create a task / Open a task" says the same thing twice and slows the scan down. Keep it where it says something the verb cannot: a consequence, or the line that tells two records apart.
- **Give at most one row action visible text.** The rest are icon-only, or the row turns into a row of buttons.
- **Never hide a gated action.** Set `availability` and let it sink to the bottom with its reason. Policy should change an action's behaviour, not its presence — a row that vanishes teaches the reader nothing.
- **State the blast radius before the commit.** For a selection, return `impact` so the row itself reads `3 of 4 · 1 is already wiped`, rather than surfacing that in the confirm dialog after the reader has committed.

### Content best practices

- Action labels are imperative
  - **Correct:** "Lock screen", "Collect diagnostics", "Reassign owner"
  - **Incorrect:** "Screen lock", "Diagnostics collection", "Owner reassignment"
- Group headings name the reader's intent, not your storage
  - **Correct:** "Security", "Maintenance", "Lifecycle"
  - **Incorrect:** "Catalog", "Scripts", "Queries" — origin belongs on the row as `badge`
- An availability reason says what is true, not what failed
  - **Correct:** "Already enrolled since March"
  - **Incorrect:** "Action unavailable", "Error: precondition not met"

## Props

`F0CommandPaletteProvider` mounts the overlay and owns whether it is open. Render it once, high in the tree.

| Prop                    | Type                                  | Default        | Description                                                                       |
| ----------------------- | ------------------------------------- | -------------- | --------------------------------------------------------------------------------- |
| `providers`             | `CommandEntityProvider[]`             | `[]`           | The domains whose records are findable, in the order their groups appear.         |
| `actions`               | `CommandAction[]`                     | `[]`           | Flat global commands. Shown under "Suggestions" on an empty query.                |
| `navigation`            | `CommandNavigationItem[]`             | `[]`           | The "Go to" group.                                                                |
| `recent`                | `string[]`                            | `[]`           | Ids of `actions` or `navigation` to lead the empty state with, most recent first. |
| `assistant`             | `CommandAssistant`                    | —              | The assistant escape hatch. Omit it and every assistant affordance disappears.    |
| `onNavigate`            | `(href: string) => void`              | full page load | How an `href` is followed. Pass your router's navigate.                           |
| `shortcut`              | `boolean`                             | `true`         | Bind `mod+K`.                                                                     |
| `open` / `onOpenChange` | `boolean` / `(open: boolean) => void` | —              | Controlled open state. Leave out to let the palette own it.                       |

`useCommandPalette()` returns `{ open, openScoped, close, isOpen }`, and throws outside the provider.

### A provider is the unit of contribution

A domain declares its records and its actions once, and every surface — a row menu, a bulk bar, the palette — is a projection of that one list rather than N×M pickers:

```tsx
const deviceProvider: CommandEntityProvider = {
  type: "device",
  label: "Devices",
  search: (query, limit) => findDevices(query).slice(0, limit),
  actions: (ref) => [
    {
      key: "lock",
      label: "Lock screen",
      icon: LockLocked,
      group: "Security",
      risk: "none",
      run: (target, values, { navigate }) => lockDevice(target, navigate),
    },
  ],
}
```

`actions` is optional. Leave it off while a domain has not adopted the registry: its records stay findable and openable, they are simply not scopable yet — a valid state, not a broken one.

### Behavior

- **`run` receives a context, never a router.** `{ navigate, ask }` is handed in, so a provider stays free of routing and of any assistant runtime. `ask` is a no-op when no `assistant` is configured.
- **A selection is a snapshot.** `kind: "many"` carries the ids captured when the palette opened, so a selection changing behind the overlay cannot redirect an action mid-flight.
- **Every open starts clean.** The panel is keyed on the open count, so opening scoped immediately after a plain open cannot inherit the previous scope.
- **`recent` is yours.** What counts as recent is a fact about your app's history, so the palette reads the list and never writes to storage on your behalf.
- **Escape is layered.** It pops one level of the grammar before it closes the overlay, so it is the way back out of a scope as well as the way out.

## Accessibility

- The bar is a `combobox` wired to the list with `aria-controls` and `aria-activedescendant`; the list is a `listbox` and every row an `option` with `aria-selected`. Selection moves without focus ever leaving the input.
- **Blocked rows stay reachable.** A gated row carries `aria-disabled` and folds its reason into its accessible name, so the reason can be read rather than inferred from an absence. Activating it re-announces instead of failing silently.
- **A live region carries what the visuals say.** Entering a scope announces the record and how many actions it has, clearing it announces that, a blocked activation announces the reason, and a copied link announces the URL.
- **Row actions are real buttons.** They are never document tab stops — the palette is one focus trap around the input, and its own `Tab` handling moves focus onto them — so they keep real accessible names and activate natively with `Enter` and `Space`. Every key belonging to the list hands focus straight back, so they are a detour of exactly one key.
- **Risk is structural, not chromatic.** A destructive row is not marked by colour at rest: the verb says it, the description says it out loud, it is never the preselected row, and `Enter` hands it to your own dialog. The row turns critical only once the reader is on it.
- The panel is a modal dialog: focus is trapped, the page behind is scroll-locked, and focus returns where it came from on close. The overlay does not tint the page, so nothing behind it loses contrast.
