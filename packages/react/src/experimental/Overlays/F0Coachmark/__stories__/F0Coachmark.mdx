# F0Coachmark

A dismissible panel anchored to an element, used to point out a feature the user has not discovered yet. It carries a title, optional supporting copy and a single call to action. For a passive hint on hover use `Tooltip`; for a message tied to the page rather than to one element use `F0Alert`; for a decision that must be resolved before continuing use `F0Dialog`.

### Design best practices

**When to use**

Reach for a coachmark when a feature is already on screen but users are walking past it, and a single sentence plus one action is enough to explain it.

### Content best practices

- Write the title as a short benefit, not a label. Sentence case, no trailing period.
- Keep the description to one or two lines. It explains the value, not the mechanics.
- Give the action a verb-first label that says where it goes.
- State the benefit
  - **Correct:** "Filters got smarter", "Save views for your team"
  - **Incorrect:** "Update", "New feature", "Notice"
- Label the action concretely
  - **Correct:** "Learn more", "Try it now", "See how it works"
  - **Incorrect:** "OK", "Got it", "Click here"

### Behavior

- **Controlled only.** `open` is required and the component never changes it. Nothing is remembered between sessions — the app owns persistence, so `onDismiss` must write to wherever that decision lives.
- **`side` is a preference.** The panel flips to the opposite side and shifts along the anchor when it would overflow the viewport, so the side you pass is not guaranteed.
- **Outside clicks do not dismiss.** Only the close button and Escape call `onDismiss`. The page behind stays interactive; the panel is not modal and does not trap focus.
- **Focus moves to the panel on open,** not to the close button, so a screen reader announces the message and Enter does not immediately discard it. On dismissal focus returns to whatever had it before.
- **`children` is an anchor, not a trigger.** It renders in place and is never made clickable — clicking it does nothing unless it already did something.

## Accessibility

The panel is a non-modal `dialog`, named by `title` and described by `description` when present.

### Screen reader behavior

- Rendered with `role="dialog"`, `aria-labelledby` pointing at the title and `aria-describedby` at the description. When `description` is omitted, `aria-describedby` is not set rather than pointing at an empty node.
- Opening moves focus to the panel itself, so the title and description are announced as a unit. The dismiss button is reached by tabbing, which keeps <kbd>Enter</kbd> from discarding the message the moment it appears.
- Because focus is moved, only show a coachmark in response to something the user did or at a natural pause. One appearing mid-task pulls focus away from what they were doing.
- The close button is icon-only and carries a translated `Close` label for screen readers.
- The arrow is decorative and conveys no information beyond the anchoring already implied by focus order.
